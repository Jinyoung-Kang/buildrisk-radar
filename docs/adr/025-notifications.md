# ADR-025 알림 — 경보와 같은 트랜잭션의 outbox, 알림함 · 서명된 웹훅

**배경** 경보는 화면을 열어야 보였다. 상용 조기경보 서비스는 관심 기업에 변화가 생기면 먼저 알려 준다.
알림은 외부로 나가는 첫 기능이라 **빠짐 · 중복 · 폭주 · SSRF · 비밀 유출**을 설계에서 막아야 한다.

## 결정

1. **Transactional outbox** — `AlertService` 가 경보를 쓰는 같은 트랜잭션(규칙 평가 청크)에서 `notify.outbox` 에 사건을 남긴다.
   경보는 생겼는데 알림이 빠지거나, 롤백된 경보가 알려지는 경우가 없다. 메시지 브로커 없이 DB 하나로(ADR-011 · 012 와 같은 원칙).
2. **알릴 사건만** — NEW(그 규칙 · 대상에 열린 경보가 없다가 생김) · REOPENED(닫힌 경보가 다시 참). 기간 규칙이 다음 분기로 **이어지기만** 한 경우와
   규칙 파라미터를 바꿔 같은 경보가 **새 버전으로 다시 생긴** 경우는 알리지 않는다 — 분기마다 · 규칙을 고칠 때마다 알림이 쏟아지지 않게.
3. **worker 가 나눔** — 30초마다 `FOR UPDATE SKIP LOCKED` 로 사건을 가져가 한 SQL 문으로 구독과 맞춘다(심각도 · 규칙 · 대상 유형 · 관심 목록만).
   같은 사람 · 경보는 알림함에 한 번, 같은 웹훅 · 경보는 전송 한 번(유니크 키). worker 가 여럿이어도 한 번만 처리.
4. **웹훅 전송** — HTTP 호출은 DB 트랜잭션 밖에서, 대기열 행은 2분 임대(SENDING)로 지킨다(죽은 worker 의 행은 임대가 끝나면 다시 가져감).
   한 웹훅으로 가는 경보는 메시지 하나에 최대 20건을 묶는다. 실패하면 1분 · 5분 · 30분 · 2시간 · 12시간 뒤 다시 보내고 6번째에 포기(DEAD),
   다시 보내도 같은 4xx(웹훅 삭제 등)와 주소 거부는 바로 포기.
5. **채널** — 알림함(화면 머리말 종 · 1분마다 읽지 않은 수), Slack Incoming Webhook, 서명된 JSON(GENERIC).
   웹훅은 관리자만 등록하고 웹훅으로 보내는 구독도 관리자만 만든다. 알림함 구독 · 관심 목록은 분석가도.

## 보안

| 위협 | 대응 |
|---|---|
| SSRF — 관리자가 적은 주소로 서버가 요청 | https · 기본 포트만, `user@` · `#` 금지. 호스트를 풀어 **모든** 주소가 공인 주소일 때만(루프백 · 사설 · 169.254 메타데이터 · CGNAT · ULA · 멀티캐스트 거부). 등록할 때와 **보낼 때마다** 다시 검사, 리다이렉트 안 따라감, 연결 3초 · 응답 5초, 응답 본문은 읽지 않음 |
| 웹훅 주소 · 비밀 유출 (Slack 주소는 경로 자체가 토큰) | AES-256-GCM 저장 암호화(키 = `NOTIFY_SECRET_KEY` 를 HMAC 으로 유도, 무작위 IV, 변조는 태그로 거부). 응답 · 화면에는 호스트만(`https://hooks.slack.com/…`), GENERIC 서명 비밀은 만들 때 한 번만 보여 줌 |
| 위조 · 재전송된 웹훅을 받는 쪽이 믿음 | GENERIC: `X-BuildRisk-Signature: sha256=HMAC(비밀, 타임스탬프 + "." + 본문)` · `X-BuildRisk-Timestamp` · `X-BuildRisk-Delivery`(중복 제거용) |
| Slack 메시지 주입(`<!channel>` · 가짜 링크) | 경보 제목 · 이름의 `& < >` 이스케이프 |
| 남의 알림 · 구독 보기 | `/api/v1/me/**` 는 조회도 로그인 필요, 주인이 아니면 404(있는지도 알리지 않음). 변경은 기존 감사 로그에 남음 |

키가 없으면 웹훅 기능만 끄고(화면에 안내) 알림함은 동작한다. `make env` 가 키를 만든다.

## 고려했지만 하지 않은 것

- **이메일** — SMTP 계정(비밀값)과 새 의존성(spring-boot-starter-mail)이 필요하다. 채널이 필요해지면 같은 대기열에 전송기만 더하면 된다.
- **SSE · WebSocket 실시간 알림** — 알림은 하루 몇 번의 규칙 평가 뒤에만 생겨 1분 폴링(읽지 않은 수 한 줄, 화면이 보일 때만)으로 충분하다. 연결을 오래 잡는 비용 · 프록시 설정을 피했다.
- **메시지 브로커(Kafka 등)** — 처리량이 작고 DB 큐(ADR-012)가 이미 있다.

## 남은 위험

- DNS 리바인딩: 검사와 연결 사이에 이름이 바뀌면 이론적으로 내부 주소로 갈 수 있다. 보낼 때마다 다시 검사하고 등록은 관리자만 하므로 받아들인다
  (완전히 막으려면 검사한 IP 로 직접 연결 — TLS SNI · 인증서 검증을 함께 다뤄야 해 범위 밖).
- 키를 바꾸면 기존 웹훅은 복호화할 수 없어 다시 등록해야 한다(전송은 DEAD 로 남고 화면에 '복호화 실패').

## 검증

- `NotifySecurityTest` — 내부 주소 14종 거부 · 공인 주소 허용 · `localhost` · 메타데이터 주소 거부, 암호문 왕복 · 변조 · 다른 키, 서명 값, Slack 이스케이프.
- `NotificationIT` — 규칙 평가 → outbox → 알림함 · 웹훅(받은 쪽에서 서명 재계산 일치, 두 경보를 메시지 하나로), 다시 평가해도 중복 없음, 503 → 백오프 · 404 → 포기, 이어진 경보는 알리지 않고 다시 열린 경보는 알림, 관심 목록 필터, 권한 · 404.
- 실제 스택: 사건을 넣고 3초 안에 worker 가 알림함에 넣음, `localhost` · `169.254.169.254` · `10.0.0.5` · http 주소 등록이 400. E2E: 종 → 구독 만들고 지우기 · 내부망 웹훅 거부 메시지.
- 보존 기간: 처리한 사건 30일 · 읽은 알림 180일 · 끝난 전송 90일(매일 03:40). 지표 `buildrisk_notify_outbox_pending` · `buildrisk_notify_deliveries_total{result}` → Grafana 패널.
