# ADR-011 Kafka/CDC · ClickHouse · Kubernetes 미도입

**결정** 도입하지 않는다.

| 후보 | 도입하지 않은 이유 | 도입을 검토할 조건 |
|---|---|---|
| Kafka / Debezium CDC | 데이터 원천이 외부 공공 API 이고 갱신 주기가 일·주·월이다. 이벤트 스트림으로 얻는 지연 단축이 없고, 정합성 핵심(청크 트랜잭션·재시작)은 Spring Batch 가 이미 준다. | 경보를 여러 소비자(알림·외부 시스템)에 실시간 전파해야 할 때 — outbox 테이블 + CDC |
| ClickHouse / BigQuery | 데이터가 수십만 행 수준(재무 원천 약 50개사 × 5년 × 4보고서 × 수백 행, 지역 통계 약 1만 행). PostgreSQL 인덱스로 API p95 < 30ms. | 유니버스를 전 상장사로 넓히거나 일별 시세를 붙여 행이 억 단위가 될 때 |
| Kubernetes | 로컬 단일 노드 데모. Docker Compose 한 줄 기동(NFR-10)이 목표다. | 여러 환경 배포·오토스케일이 필요할 때 — app/batch 가 이미 같은 이미지·다른 프로필이라 Deployment + CronJob 으로 옮기기 쉽다 |

과한 인프라는 포트폴리오에서 "왜 필요했는가"에 답하기 어렵다. 대신 각 기술을 쓰지 않은 이유와 도입 조건을 기록한다.
