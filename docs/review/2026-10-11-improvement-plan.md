# 코드 리뷰 · 개선 계획 (2026-10-11, 2차)

AWS 데모에 올라간 코드(main `491a95d` — 서버 `HEAD` 와 같음을 확인)를 다시 리뷰했다. 1차 리뷰(2026-10-09, [계획](2026-10-09-improvement-plan.md))
뒤에 바뀐 코드(ADR-031 AWS 배포, 문제 169~171)와 1차가 놓친 곳이 대상이다. 문제 번호는 1차를 이어 쓴다(SEC-15~, DL-20~, FE-12~).

## 7. 하지 않는 것 (이유)

- **`IllegalArgumentException` → 400 일괄 변경**: JDK 의 숫자 형식 오류처럼 의도된 400 이 같은 예외로 오므로 일괄로 바꾸면 위험이 이득보다 큼.
- **심각도 `CASE` 등 SQL 의 작은 중복**(7곳): 지금 어긋난 곳이 없음. **출처 표 ID 의 코드 고정**: 실데이터로 확인한 값이고 바뀔 일이 드묾 — 남은 위험으로 기록.
- **로컬 개발 DB 16 → 18**: 로컬 데이터 볼륨을 덤프 · 복원해야 함. 테스트만 18 로 맞추고 로컬은 원하실 때.
- **AWS 요청 한도 · `statement_timeout` · Hikari 대기 시간 조정**: RDS 에서 잴 수 없어 숫자를 정할 근거가 없음 — PERF-1 · 2 로 풀 부담을 줄이고 나머지는 다음 단계 제안.
- **React 19 · Grafana 13**: 메이저 업그레이드, 지원 종료 아님.
- **시한이 남은 고정값**: SGIS 가구 연도(2024), 실거래 파티션(2030), 기간 형식(2029Q4) — 다음 단계로 기록.
